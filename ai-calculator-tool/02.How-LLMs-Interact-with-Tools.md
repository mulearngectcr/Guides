## 📖 Introduction

Now that you understand **why** LLMs need tools, let's understand **how** they use them.

The interaction between you, the LLM, and your tools follows a specific pattern. Understanding this pattern is crucial to building effective tools.

---

## 🔄 The Function Calling Workflow

Let me show you the complete flow with our calculator example:

### Step-by-Step Breakdown

```
┌─────────────────────────────────────────────────────────────┐
│ STEP 1: USER SENDS A QUESTION                               │
└─────────────────────────────────────────────────────────────┘

User Input: "What is 18% of 2500?"

        │
        ▼

┌─────────────────────────────────────────────────────────────┐
│ STEP 2: LLM RECEIVES THE QUESTION & TOOL DEFINITIONS        │
└─────────────────────────────────────────────────────────────┘

LLM receives:
  1. The question
  2. A list of available tools (the calculator tool)
  3. Descriptions of what each tool does

LLM Thinks: "The user wants a calculation. I should use the
calculator tool. The expression is: 2500 * 0.18"

        │
        ▼

┌─────────────────────────────────────────────────────────────┐
│ STEP 3: LLM DECIDES TO USE A TOOL                           │
└─────────────────────────────────────────────────────────────┘

LLM's Response:
{
  "type": "function_call",
  "function": {
    "name": "calculator",
    "arguments": {
      "expression": "2500 * 0.18"
    }
  }
}

        │
        ▼

┌─────────────────────────────────────────────────────────────┐
│ STEP 4: YOUR CODE EXECUTES THE TOOL                         │
└─────────────────────────────────────────────────────────────┘

Your Python Code:
  result = calculator(expression="2500 * 0.18")
  # result = 450.0

        │
        ▼

┌─────────────────────────────────────────────────────────────┐
│ STEP 5: SEND THE RESULT BACK TO THE LLM                     │
└─────────────────────────────────────────────────────────────┘

You send back:
{
  "role": "tool",
  "content": "450.0",
  "tool_call_id": "call_123"
}

        │
        ▼

┌─────────────────────────────────────────────────────────────┐
│ STEP 6: LLM GENERATES FINAL RESPONSE                        │
└─────────────────────────────────────────────────────────────┘

LLM Response: "18% of 2500 is 450."

        │
        ▼

┌─────────────────────────────────────────────────────────────┐
│ STEP 7: RESPONSE GOES TO USER                               │
└─────────────────────────────────────────────────────────────┘

User sees: "18% of 2500 is 450."
```

## 🛠️ Understanding Tool Definitions

For the LLM to know about your calculator, you must provide a **tool definition**. This is a JSON schema that describes your tool.

### Simple Tool Definition

```python
calculator_tool = {
    "name": "calculator",
    "description": "Performs mathematical calculations on expressions",
    "parameters": {
        "type": "object",
        "properties": {
            "expression": {
                "type": "string",
                "description": "Mathematical expression to evaluate (e.g., '2500 * 0.18')"
            }
        },
        "required": ["expression"]
    }
}
```

### Breaking It Down

**Name:**

```python
"name": "calculator"
```

The exact name the LLM will use when calling your tool. Keep it simple and descriptive.

**Description:**

```python
"description": "Performs mathematical calculations on expressions"
```

Tell the LLM what this tool does. Be clear and specific. The LLM uses this to decide whether to use the tool.

**Parameters:**

```python
"parameters": {
    "type": "object",  # This is always "object"
    "properties": {    # Describe each input parameter
        "expression": {
            "type": "string",
            "description": "Mathematical expression to evaluate"
        }
    },
    "required": ["expression"]  # Which parameters are mandatory
}
```

## 📋 Tool Parameters Explained

Parameters are the inputs your tool needs. Let's look at different parameter types:

### Single Required Parameter

**Tool Definition:**

```python
{
    "name": "add_numbers",
    "description": "Adds two numbers together",
    "parameters": {
        "type": "object",
        "properties": {
            "num1": {
                "type": "number",
                "description": "First number"
            },
            "num2": {
                "type": "number",
                "description": "Second number"
            }
        },
        "required": ["num1", "num2"]
    }
}
```

**Function Implementation:**

```python
def add_numbers(num1: float, num2: float) -> float:
    return num1 + num2
```

**LLM Usage:**

```
User: "What is 5 + 3?"

LLM: I'll use add_numbers tool.
🛠️  Tool Call: add_numbers(num1=5, num2=3)
Result: 8
```

### Multiple Parameters with Optional Fields

**Tool Definition:**

```python
{
    "name": "weather",
    "description": "Gets weather information",
    "parameters": {
        "type": "object",
        "properties": {
            "city": {
                "type": "string",
                "description": "City name"
            },
            "unit": {
                "type": "string",
                "enum": ["celsius", "fahrenheit"],
                "description": "Temperature unit (optional, defaults to celsius)"
            }
        },
        "required": ["city"]  # Only city is required
    }
}
```

**Function Implementation:**

```python
def weather(city: str, unit: str = "celsius") -> str:
    # Get weather data
    return f"Weather in {city}: 25 {unit}"
```

**LLM Usage:**

```
User: "What's the weather in London?"

LLM: I'll call weather with only the city.
🛠️  Tool Call: weather(city="London")
Result: "Weather in London: 25 celsius"

User: "Tell me in Fahrenheit"

LLM: I'll call weather with both parameters.
🛠️  Tool Call: weather(city="London", unit="fahrenheit")
Result: "Weather in London: 77 fahrenheit"
```

## 💬 The Conversation Loop

This is how the conversation flows between you, the LLM, and tools:

### Initial Message

```python
messages = [
    {
        "role": "user",
        "content": "What is 18% of 2500?"
    }
]
```

### LLM Response (Tool Call)

```python
response = {
    "choices": [
        {
            "message": {
                "role": "assistant",
                "content": None,
                "tool_calls": [
                    {
                        "id": "call_1",
                        "function": {
                            "name": "calculator",
                            "arguments": '{"expression": "2500 * 0.18"}'
                        }
                    }
                ]
            }
        }
    ]
}
```

### Add Tool Result to Conversation

```python
messages.append({
    "role": "assistant",
    "content": None,
    "tool_calls": [
        {
            "id": "call_1",
            "function": {
                "name": "calculator",
                "arguments": '{"expression": "2500 * 0.18"}'
            }
        }
    ]
})

# Execute the tool
result = calculator("2500 * 0.18")  # Returns 450.0

# Add tool result to conversation
messages.append({
    "role": "tool",
    "tool_call_id": "call_1",
    "content": "450.0"
})
```

### Final LLM Response

```python
response = {
    "choices": [
        {
            "message": {
                "role": "assistant",
                "content": "18% of 2500 is 450."
            }
        }
    ]
}
```

## ⚠️ Important Considerations

### Tool Calling is Not Guaranteed

The LLM might not always decide to use a tool, even if you've defined one.

**Example:**

```
User: "Who was Albert Einstein?"

LLM: Albert Einstein was a theoretical physicist...
(No tool call needed - this is general knowledge)
```

### Tool Calling Can Be Wrong

The LLM might misuse a tool or call it with wrong parameters.

**Example:**

```
User: "Add the words 'hello' and 'world'"

LLM: I'll use add_numbers(num1="hello", num2="world")
(Wrong! This tool expects numbers, not strings)
```

This is why error handling is important.

### Multiple Tool Calls

Sometimes the LLM needs to call multiple tools.

**Example:**

```
User: "What's the weather in London and Paris?"

LLM:
🛠️  Tool Call 1: weather(city="London")
🛠️  Tool Call 2: weather(city="Paris")
Results received, synthesizing answer...
```

---

## 📌 Key Takeaways

- Function calling follows a specific **workflow**: question → tool definition → LLM decision → execution → result → final response
- **Tool definitions** tell the LLM what tools exist and how to use them
- **Parameters** describe what inputs a tool needs
- The conversation with the LLM includes multiple **back-and-forth exchanges**
- **Error handling** is important because LLMs aren't perfect
